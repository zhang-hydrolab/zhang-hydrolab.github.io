# 内容维护指南

本指南面向课题组成员。日常更新网站不需要写代码，只需在本机运行后台、在网页中填写内容，然后发布。

## 第一次使用

1. 安装 [Node.js](https://nodejs.org/) 22.13 或更高版本。
2. 克隆本仓库，在仓库根目录运行：

   ```bash
   npm run setup
   ```

这一步只需做一次。

## 日常更新流程

1. 先拉取最新内容，避免覆盖别人的修改：

   ```bash
   git pull
   ```

2. 启动后台：

   ```bash
   npm run backend
   ```

3. 用浏览器打开 <http://127.0.0.1:8787/admin/>。在左下角填写姓名，修改记录会署上这个名字。
4. 添加或修改内容，保存。
5. 在左侧进入 **Publish**，填写本次改动说明，点击 **Build the site**。系统会自动保存一份快照、重新生成全部页面并检查所有链接。
6. 确认无误后提交并推送：

   ```bash
   git add -A
   git commit -m "Add 2026 paper"
   git push
   ```

推送后几分钟内网站就会更新。

> 保存只写入本机数据库，访客看不到。必须完成第 5、6 步，改动才会上线。

## 常见操作

### 添加论文

进入 **Publications**，点击 **New**，在绿色输入框中填入 DOI，点击 **Fill from DOI**，标题、作者、期刊等会自动填好。

请务必核对自动填入的内容，尤其是作者姓名。作者使用 APA 格式，例如 `Zhang, Y., Ma, N., & Tian, J.`。网站会自动加粗 Zhang, Y.。

**Topics** 用英文逗号分隔，决定论文页的主题筛选。请尽量沿用已有主题，例如 `Evapotranspiration, Drought`。勾选 **Highlighted paper** 后，论文可出现在首页。

### 发布新闻

进入 **News**，点击 **New**。中英文标题至少填写一个，建议都填。

- 只填 **Source link**：点击新闻后跳转到外部链接。
- 填写 **Article body**：网站会为这条新闻生成独立页面。正文使用 Markdown。
- 勾选 **Feature on homepage**：出现在首页的研究亮点中。

新闻按年份、具体日期倒序排列；同日使用 **Sort order** 决定顺序。请填写可核实的日期，不清楚具体日期时留空，该新闻会排在同年有日期的新闻之后。公众号快讯使用原文发布日期，会议使用开幕日期并在摘要或正文写明起止日期。

人才、基金资助及任职新闻建议每人单独建一条，封面选择已有成员照片；正文填写该人的研究方向及相关成果。资助项目名称、日期以当事人确认或正式公告为准，不补写未经核实的金额或编号。

### 添加成员

进入 **People**，点击 **New**，填写姓名和身份，并上传照片。如果头像被裁切，可调整 **Photo focus**：`50% 25%` 表示水平居中、取偏上的部分，第二个数字越小，画面越靠上。

请同时填写中英文研究方向（**Research field**）和简介（**Bio**）。成员卡片与详情会跟随右上角语言按钮切换。网站在新的浏览会话中默认使用英文，当前会话内保留主动选择的语言。

邮箱填写在 **Email**；Google Scholar、GitHub、个人主页、ResearchGate 和 ORCID 填写在 **Links**，每条填写名称与真实地址。个人主页名称使用 `Homepage`。已有链接会在照片下方及详情中显示为可单独点击的圆形图标，未填写的链接不会显示；其他类型链接仍会显示为通用链接图标。

### 成员毕业

不要归档或删除，把 **Role** 改为 `alumni` 即可，这位成员会移到校友列表。

### 更新首页数字

引用量、H 指数等都在 **Site settings** 的 `site.stats` 中。设置项是 JSON 格式，保存时如果格式有误，系统会拒绝并提示。

招生信息在 `site.recruitment`，联系方式在 `site.contact`。

首页的“课题组简介”取自 `site.pi` 的 `bio_en` 和 `bio_zh`，这两个列表都按段落顺序读取：前两段介绍团队负责人，在首页折叠显示；第三段起介绍团队，在首页直接显示。修改时请保持这个顺序。人员页默认显示 **People** 中负责人的中英文 **Bio** 简介；完整的 `site.pi` 段落保留在“了解更多团队与负责人介绍”中，展开后阅读。

### 上传文件

进入 **Files**，把图片或 PDF 拖入虚线框。支持 JPEG、PNG、WebP、GIF 和 PDF，单个文件不超过 40 MB。出于安全考虑，不支持 SVG。

原图会原样存入档案，网站发布时自动生成多种尺寸的 WebP。请为图片填写说明文字，方便视障读者使用。

## 下架与恢复

| 操作 | 效果 | 能否恢复 |
| --- | --- | --- |
| 改为 `draft` | 不在网站显示，但保留在列表中 | 随时改回 `published` |
| **Archive** | 从网站移除，保留全部数据 | 点击 **Restore** |
| **Delete** | 删除记录，只有已归档的内容才能删除 | 可在 **Change history** 中回滚 |

平时请优先使用归档，而不是删除。

## 找回旧版本

- 改错了某一条：打开这条内容，在页面下方的 **History** 中点击 **Roll back**。
- 需要整体回退：进入 **Snapshots**，选择某次快照并点击 **Restore**。当前状态会先被记录，所以恢复操作本身也可以撤销。

## 注意事项

**仓库是公开的。** `backend/content/` 中的所有内容都在公开仓库里，草稿和已归档的内容也不例外，任何人都能看到。`draft` 的意思是“不在网站显示”，而不是“保密”。请不要把身份证号、个人手机号、未公开的数据或任何密码存入后台。

**不要手动修改根目录的 HTML、`assets/`、`media/`、`news/`、`api/`。** 这些文件由发布脚本生成，下次发布时会被覆盖。

**首页地球和各页 3D 地形不在后台维护。** 它们由 `frontend/tools/` 中的脚本根据本地数据生成，日常更新内容时无需改动，详见 `docs/architecture.md` 的“3D views”。

**多人同时维护时**，每次开始前先 `git pull`，完成后尽快推送。如果同一个文件发生冲突，因为 `backend/content/*.ndjson` 每行一条记录，通常保留双方的行即可。

## 遇到问题

| 现象 | 处理办法 |
| --- | --- |
| 后台打不开 | 确认 `npm run backend` 仍在运行 |
| 发布失败 | 查看页面上的日志。发布失败时线上文件不会改动 |
| 提示链接损坏 | 按日志修改对应内容后重新发布 |
| 推送后网站没有更新 | 等几分钟后强制刷新；在 GitHub 的 Actions 页面查看 `pages build and deployment` 是否成功 |
